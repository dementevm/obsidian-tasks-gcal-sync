# Tasks Google Calendar Sync

Privacy-first, one-way synchronization from **Obsidian Tasks** to **Google Calendar**, with desktop and mobile support.

> [!IMPORTANT]
> Every user must create their **own Google Cloud OAuth client**. This plugin does not ship with a shared Google client ID or client secret.

## Why this project exists

This project is a substantially modified derivative of [Sasoon/obsidian-gcal-sync](https://github.com/Sasoon/obsidian-gcal-sync).

The upstream project provided the core idea and much of the original implementation: turn dated Obsidian tasks into Google Calendar events. This fork was created because our workflow needed a different security and synchronization model:

- no shared OAuth client or server-side token exchange owned by the plugin author;
- user-owned Google OAuth credentials;
- OAuth secrets stored with Obsidian SecretStorage instead of plugin `data.json`;
- a static, auditable OAuth redirect bridge with no server-side processing;
- a dedicated target calendar instead of always relying on `primary`;
- explicit confirmation before the primary calendar can be used;
- opt-in whole-vault scanning;
- explicit, previewed cleanup instead of automatic destructive repair;
- reliable compatibility with recurring tasks created by the Obsidian Tasks plugin;
- informational calendar reminders in addition to checkbox tasks;
- better desktop/iOS behavior, setup transfer, diagnostics, time-zone handling, and editor shortcuts.

The project remains licensed under **GPL-3.0**, matching the upstream project. See [License and attribution](#license-and-attribution).

## Features

### One-way sync: Obsidian → Google Calendar

Obsidian is the source of truth.

The plugin can:

- create Google Calendar events from dated Obsidian tasks;
- update events when the task title, date, time, reminder, duration, or file location changes;
- delete the managed Google event when a tracked task is completed or explicitly removed from calendar tracking;
- handle recurring occurrences generated by the Obsidian Tasks plugin without reusing the previous occurrence's private ID;
- create informational `📆` events that do not have checkbox/completion state;
- sync manually or automatically;
- work on desktop and mobile, including iOS.

Changes made directly in Google Calendar are **not imported back into Obsidian**.

### Explicit sync scope

Calendar synchronization is opt-in in two ways:

1. an item must contain a `📅 YYYY-MM-DD` date marker;
2. the file must be inside the configured sync scope.

You can either:

- select specific folders/files; or
- explicitly enable **Scan Entire Vault**.

If configured folders cannot be found, the plugin stops safely. It does not silently fall back to scanning the whole vault.

### Safer calendar targeting

A dedicated Google calendar, for example **Obsidian Tasks**, is strongly recommended.

Using `primary` is supported, but must be confirmed locally on the device. That consent is deliberately not copied in setup links.

### Recurring Obsidian Tasks

Recurrence belongs to the **Obsidian Tasks** plugin, not Google Calendar.

Each occurrence becomes an independent Google event. The plugin stores a hidden marker immediately after the checkbox:

```markdown
- [ ] <!-- task-id: abc123 --> Pay subscription 🔁 every month 📅 2026-10-01
```

When Obsidian Tasks completes an occurrence and creates the next one:

- the completed occurrence keeps its ID;
- the new occurrence gets a fresh ID;
- the completed occurrence's Google event is removed;
- the new occurrence gets its own event.

The ID position is intentional. Putting unknown metadata at the end of a task line can interfere with the way Obsidian Tasks parses recurrence/date metadata.

### Informational events

Use `📆` for calendar reminders that are not actionable tasks:

```markdown
- 📆 Dentist 📅 2026-09-25 ⏰ 15:00 🔔1h
```

If a `📆` event has no explicit time, the plugin uses **Morning Event Time** (09:00 by default).

### Editor shortcuts

On a Markdown list line, type `@` to open calendar metadata suggestions:

| Shortcut | Inserts | Meaning |
| --- | --- | --- |
| `@event` | 📆 | Informational event |
| `@date` | 📅 | Calendar date |
| `@time` | ⏰ | Start time |
| `@rem` | 🔔 | Reminder |
| `@dur` | ⏱ | Duration |
| `@end` | ➡️ | Explicit end time |

You can also run **Tasks GCal: Create calendar reminder** from the command palette.

## Task syntax

A date is required for synchronization.

```markdown
- [ ] All-day task 📅 2026-09-25
- [ ] Meeting 📅 2026-09-25 ⏰ 14:30
- [ ] Meeting 📅 2026-09-25 ⏰ 14:30 🔔30m
- [ ] Focus block 📅 2026-09-25 ⏰ 14:30 ⏱45m 🔔10m
- [ ] Appointment 📅 2026-09-25 ⏰ 23:30 ➡️ 00:30
- 📆 Morning reminder 📅 2026-09-25
- 📆 Flight check-in 📅 2026-09-25 ⏰ 18:00 🔔1d
```

Supported plugin metadata:

- `📅 YYYY-MM-DD` — date;
- `⏰ HH:MM` — start time;
- `➡️ HH:MM` — explicit end time;
- `⏱20m`, `⏱2h` — duration;
- `🔔30m`, `🔔2h`, `🔔1d` — popup reminder.

If `➡️` is earlier than or equal to the start time, the event ends on the following day. Explicit `➡️` takes precedence over `⏱`.

Ordinary undated checklists are ignored:

```markdown
- [ ] Milk
- [ ] Cat litter
- [ ] Coffee
```

## Time zones

Timed items capture the device's current IANA time zone when first synchronized and keep that zone in task metadata.

For example, if you create an event for 19:00 while your device is in `Asia/Seoul`, a later background sync from `Europe/Amsterdam` does not reinterpret that event as 19:00 Amsterdam time.

## Reminders

Default reminder profiles are independent:

- timed checkbox task: 30 minutes before;
- `📆` informational event: at event start;
- `📆` without `⏰`: Morning Event Time, 09:00 by default;
- timed item duration: 5 minutes by default;
- all-day checkbox task: no popup by default.

An explicit `🔔` value overrides the corresponding default.

## Google Cloud setup

Each user creates a personal Google OAuth client. **Do not use somebody else's client ID/client secret.**

The plugin requests only this Google Calendar scope:

```text
https://www.googleapis.com/auth/calendar.events.owned
```

Google describes this scope as permission to see, create, change, and delete events on calendars that the user owns.

### 1. Create a Google Cloud project

1. Open [Google Cloud Console](https://console.cloud.google.com/).
2. Create a new project, or select a project dedicated to this plugin.
3. Open **APIs & Services → Library**.
4. Find **Google Calendar API**.
5. Click **Enable**.

### 2. Configure Google Auth Platform / OAuth consent

Open **Google Auth Platform** for the project and configure:

1. **Branding** — choose an app name such as `My Obsidian Calendar Sync`, and provide the requested contact/support email.
2. **Audience**:
   - for a normal personal Google account, choose **External**;
   - a Google Workspace organization may use **Internal** if appropriate for that organization.
3. **Data Access** — add only:
   ```text
   https://www.googleapis.com/auth/calendar.events.owned
   ```

For an External app you can initially leave the project in **Testing** and add your own Google account as a test user.

**Important:** Google states that an External OAuth app in Testing normally receives refresh tokens that expire after 7 days when non-basic scopes are requested. Once your personal setup works, switch the OAuth app to **In production** if you want persistent authorization. Google may still show an unverified-app warning for an unverified external app.

Because this plugin uses a separate OAuth client owned by each user, you do not share the plugin author's OAuth user quota or credentials.

### 3. Create the OAuth client

1. In Google Auth Platform, open **Clients**.
2. Choose **Create client**.
3. Application type: **Web application**.
4. Add this exact **Authorized redirect URI**:

   ```text
   https://dementevm.github.io/obsidian-tasks-gcal-sync-bridge/
   ```

   The scheme, host, path, and trailing slash must match exactly.
5. Create the client.
6. Copy the generated:
   - **Client ID**
   - **Client Secret**

Never commit the client secret to a repository or paste it into a public issue.

### 4. Create a dedicated Google calendar

A dedicated calendar is safer than using your primary calendar.

In Google Calendar:

1. create a calendar such as **Obsidian Tasks**;
2. open that calendar's **Settings and sharing**;
3. find **Integrate calendar → Calendar ID**;
4. copy the Calendar ID.

The requested `calendar.events.owned` scope only allows the plugin to manage events on calendars you own.

### 5. Configure Obsidian

Open **Settings → Tasks Google Calendar Sync**:

1. **Calendar ID** → paste the dedicated calendar ID.
2. **OAuth Client ID** → paste your Google Client ID.
3. **OAuth Client Secret** → create/select an Obsidian SecretStorage entry and store your Google Client Secret there.
4. Choose the folders/files to sync, or explicitly enable **Scan Entire Vault**.
5. Leave **Auto-sync** off for the first test.
6. Click the plugin ribbon/status action and connect to Google.
7. Authorize the requested Calendar permission.
8. Create one test task and run **Sync now**.
9. After verifying the test calendar, enable Auto-sync if desired.

## OAuth and privacy model

```text
Obsidian
   |
   | authorization request + PKCE + state
   v
Google
   |
   | short-lived authorization code + state
   v
Static GitHub Pages bridge
   |
   | obsidian://auth/gcalsync
   v
Obsidian
   |
   | code + PKCE verifier + your client secret
   v
Google token endpoint

Obsidian Tasks -----------------------> Google Calendar API
```

The redirect bridge is public and auditable:

- source: [dementevm/obsidian-tasks-gcal-sync-bridge](https://github.com/dementevm/obsidian-tasks-gcal-sync-bridge);
- no server-side code;
- no client secret;
- no token exchange;
- no analytics;
- no storage of calendar/vault data;
- it removes Google's authorization response from the browser address bar before returning to Obsidian.

The plugin communicates with:

- `accounts.google.com` — OAuth authorization;
- `oauth2.googleapis.com` — token exchange, refresh, and revocation;
- `www.googleapis.com/calendar/v3` — Google Calendar API;
- `dementevm.github.io/obsidian-tasks-gcal-sync-bridge/` — static OAuth redirect bridge.

### Secret storage

The Google Client Secret and refresh token are stored using Obsidian **SecretStorage**, not in this plugin's `data.json`.

The access token is kept in memory and refreshed when needed.

PKCE state/verifier are stored only as temporary device-local OAuth state and are cleared after the OAuth callback.

Normal non-secret plugin settings can be synchronized by your chosen Obsidian synchronization solution.

### Setup links

**Copy Setup Link** creates an `obsidian://tasks-gcal-sync/setup?... ` link for another device.

The link may include non-secret configuration such as:

- Client ID;
- Calendar ID;
- folders/scope;
- reminder defaults;
- mobile settings.

It does **not** contain:

- OAuth Client Secret;
- access/refresh token;
- task metadata;
- private task IDs;
- Auto-sync=ON consent;
- primary-calendar consent;
- a custom OAuth redirect host.

Opening a setup link always requires local confirmation, and Auto-sync remains off after import.

## Destructive operations and safety

The plugin intentionally avoids automatic destructive repair.

**Sync now** can apply explicit user actions such as:

- completing a tracked task;
- deleting a tracked line;
- removing `📅` from a tracked line.

Generic orphan/duplicate cleanup is available only through an explicit **Clean orphaned items** / **Repair** action with confirmation.

Plugin reload/unload does not perform remote cleanup.

Google Calendar events created by the plugin carry private extended properties that associate them with their Obsidian task ID.

## Diagnostics

Use **Google Calendar: Open diagnostics** from the command palette to inspect:

- authentication status;
- availability of the selected client secret;
- Calendar ID;
- primary-calendar confirmation;
- sync scope;
- Auto-sync state;
- device time zone;
- tracked item count;
- pending/failed syncs;
- last sync and last error.

Verbose logging is disabled by default. When enabled for troubleshooting, console logs may include task titles, task IDs, file paths, dates, and other synchronization metadata. OAuth tokens and client secrets should never be logged.

## Device setup

The plugin supports desktop and mobile Obsidian.

For another device:

1. install/sync the plugin;
2. use **Copy Setup Link** from an existing device, or configure settings manually;
3. create/select the Client Secret entry in SecretStorage on that device;
4. connect that device to Google.

OAuth authorization is intentionally completed per device.

## Installation

### Community Plugins

The project is being prepared for submission to the official Obsidian Community Plugins directory.

Once accepted:

1. open **Settings → Community plugins → Browse**;
2. search for **Tasks Google Calendar Sync**;
3. install and enable it.

### Manual installation / beta testing

Until the Community directory release is available:

1. download `main.js`, `manifest.json`, and `styles.css` from a GitHub release;
2. create:
   ```text
   <vault>/.obsidian/plugins/tasks-gcal-sync/
   ```
3. copy the three files into that folder;
4. reload Obsidian;
5. enable **Tasks Google Calendar Sync** in Community plugins.

A GitHub/BRAT beta can also be used before Community directory acceptance.

```bash
npm run build
```

- `main.js`
- `manifest.json`
- `styles.css`

## Known design choices

- Sync is deliberately **one-way**.
- Google recurring series are not used; recurrence remains owned by Obsidian Tasks.
- A dedicated owned Google calendar is recommended.
- Each user must supply their own Google OAuth client.
- Whole-vault scanning must be explicitly enabled.
- Generic orphan cleanup is never automatic.
